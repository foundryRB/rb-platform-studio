**Date**: 2026-07-04 (promotion freeze added 2026-07-27; the upstream-head start, the refusals on a conflict or unparseable file, and the reconcile carry-over added 2026-10-11)
**Status**: Decided
**Amended**: 2026-08-27. [ADR-009](../adr-009/) moved the studio's one writable branch from `main` to the install's deploy branch; the toggles direct-commit there now, the one exception to the PR-only rule. Where this record says "main" or "the default branch", read the install's deploy branch. The mechanism (the narrow edit, the byte-for-byte reverse, the refusals) is unchanged.

## Context

[ADR-002](../adr-002/) has every onboarding action ship as a pull request the maintainer merges, because a write to the platform repo's `main` is a deployment and admitting an app or granting its hostname are deliberate decisions. Not every write to `platform/` is such a decision. To manage capacity on a single node, an operator needs to pause an onboarded app (scale its workload to zero) and resume it, quickly, for any app. Pausing keeps the app's namespace, routing, database, and identity and only stops its pods; it admits no app and grants no hostname, and it is fully reversible. The platform-side mechanism, an override on the app's ArgoCD Application, is defined by the platform's own decision record (its ADR-030); this record fixes how the studio writes it.

A second toggle has the same shape. Image promotion is automatic by the platform's own decision (its ADR-022): ArgoCD Image Updater watches GHCR and writes each new released tag into the app's `deploy-<install>` branch, so a push to `main` reaches prod with no hand. An operator sometimes needs the opposite for one app - hold it through an incident, hold it for a demo, hold it while a migration lands - and then set the version deliberately. That stance is operational and reversible in exactly the way a pause is, and it is written to the same platform-owned Application.

## Decision

Lifecycle toggles direct-commit to the default branch. Each toggle:

- writes only its own narrow edit into the app's team manifest, leaving every other byte untouched, and restores the manifest byte-for-byte on the reverse toggle:
  - pause writes the scale-to-zero override (`spec.source.helm.valuesObject.<app>.paused`);
  - freeze writes one Image Updater tag filter per alias the Application's `image-list` declares (`<alias>.ignore-tags: "*"`);
- commits that one file directly to the default branch (`chore(lifecycle): pause <app>` / `resume <app>`, `chore(lifecycle): freeze promotion for <app>` / `resume promotion for <app>`), opening no branch and no pull request;
- starts from the default branch's upstream head: the studio's clone is brought to it before the toggle reads or edits a file, and the edit is committed as it stands, never stashed. When the branch moves again before the push, the commit is rebased onto the new head; a rebase conflict, or a file carrying conflict markers or failing to parse as YAML, refuses the toggle, leaving the remote untouched and the clone on the upstream head;
- is gated by lightweight validation (the app is registered and onboarded; the write is the narrow edit), not the conformance suite;
- refuses rather than silently succeeding when the manifest cannot take the edit: pause refuses an Application already carrying a `spec.source.helm` block, and freeze refuses one declaring no `image-list` (nothing promotes it already) or an alias already carrying an `ignore-tags` that is not the freeze sentinel (an operator's own filter).

Pause refuses the studio's own app, which would scale away the control plane that resumes it. Freeze does not: holding the studio on its current version leaves it running and able to unfreeze itself.

The two are read and reported apart, because they are independent: an app can be paused and still promoting (it takes the newer tag when it resumes), or running and frozen. The status is `running`/`paused`; the promotion mode is `auto`, `manual`, or `none` (an Application with no bindings at all).

Both survive a reconcile. Reconcile re-renders the Application from the canonical template, which is neither frozen nor paused, and then re-applies what the branch it is based on carries: the freeze on every alias the fresh declaration names, new ones included, and the scale-to-zero override.

This is a bounded carve-out from ADR-002: onboarding changes still never commit to `main`. The behavior is attested by INT-LIFECYCLE-001 to INT-LIFECYCLE-004.

## Rationale

- An operational toggle is not an admission decision. ADR-002's maintainer gate protects admitting an app and granting its hostname; neither a pause nor a freeze does either, so routing the toggle through a pull request adds latency without protecting a deliberate choice.
- The operator wants the switch to be quick and to reach any app; a PR-per-toggle round trip works against that.
- The blast radius is minimal: each edit is a single narrow key or one line per alias, and the reverse toggle restores the manifest byte-for-byte, so the change is both bounded and reversible. The studio still mutates only its own datastore ([ADR-006](../adr-006/)); the direct commit is the git history's own audit trail.
- The direct commit has no gate behind it, so it must never be the step that breaks an Application. The studio's clone is long-lived and the branch moves under it (the platform CI merges the studio's own pull requests); an edit made on a stale clone and carried over the new head through a stash once conflicted on the stash pop and pushed `application.yaml` with the conflict markers in it. Starting from the upstream head, committing before rebasing, and refusing on a conflict or an unparseable file make the remote take a toggle whole or not at all.
- A toggle is the operator's standing decision, not drift. Reconcile exists to repair drift from the canonical render, so it would otherwise undo a hold the operator still wants, silently, on merge.
- The freeze is a tag filter rather than a removal of the Image Updater annotations because Image Updater selects its working set on `image-list`. Removing the annotations does stop promotion, but it also takes the app out of the promotion conformance rows (shape, values binding, released set) and out of the deploy-branch status read, which both key on those annotations: the app would stop promoting and stop being watched for the silent never-promotes class those rows exist to catch. A filter of `*` leaves every binding in place and simply leaves no candidate tag, so a frozen app stays fully verified.

## Alternatives considered and rejected

- **PR-per-toggle, gated like onboarding**: consistent with ADR-002, but slow, and it applies the admission gate to a change that admits nothing.
- **Auto-merged pull request**: keeps a PR trail but still round-trips through GitHub for a reversible one-key toggle; the direct commit is simpler and the commit is the trail.
- **Commit the pause on the app's own deploy branch**: the studio has no write access there and mutates only `platform/` ([ADR-006](../adr-006/)); pause is a platform-authority capacity decision, not team version config, so it belongs on the platform-owned Application, not the team's deploy branch.
- **Freeze by removing the Image Updater annotations**: the officially clean opt-out, and it costs the conformance rows and the status read, as above.
- **Freeze by pinning a version constraint in `image-list`** (`app=ghcr.io/<org>/<app>:1.4.2`): real Image Updater behaviour, but the canonical binding shape the studio renders and the install conformance holds every Application to (INT-PROMOTE-002) requires the watched image to be exactly `ghcr.io/<owner>/<package>`, so a constraint reads as shape drift and turns the app's row red.
- **Declare auto-versus-manual once at onboarding**: an app's promotion stance changes over its life, and an onboarding-time flag would leave every later change as a hand edit of the deploy branch - the act the studio exists to replace. A per-app onboarding declaration remains possible later, but it would have to be a manifest fact with a conformance row holding the Application to it, not a render-time convenience that drifts on the first hand edit.
