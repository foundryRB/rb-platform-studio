**Date**: 2026-07-04
**Status**: Decided
**Amended**: 2026-08-27. The platform's identity grant (its ADR-031) put an oauth2-proxy OIDC gate in front of the human surfaces, and the chart now defaults to it: `STUDIO_AUTH_SCOPE=mcp` narrows this record's Basic gate to the `/mcp` machine door, which cannot complete an interactive login. Stood up without the proxy, the Basic gate still covers all three surfaces exactly as decided here; the fail-closed rule holds in both postures.

## Context

The studio serves on a public hostname and holds write access to the cluster's control-plane repo. Every surface (SPA, `/api`, `/mcp`) needs gating before the instance serves anything.

## Decision

HTTP Basic auth gates all three surfaces with a single shared credential, fail-closed: the chart names `auth.existingSecret: platform-studio-auth`, and protected routes answer 503 until the Secret is provisioned out of band. `/api/health` is exempt so probes work before and after the credential exists. Browsers get the native prompt; MCP clients pass the `Authorization` header.

## Rationale

- Fail-closed means a misconfigured instance is closed, never silently open, which is what makes publishing the hostname safe for a surface that can open PRs against the control plane.
- One mechanism covers all three surfaces; MCP clients speak HTTP and carry headers natively.
- The health exemption keeps Kubernetes probes independent of the credential's lifecycle; the pod can report ready while correctly refusing everything else.

## Alternatives considered and rejected

- **A second auth scheme for MCP** (tokens, OAuth): more machinery for the same single-maintainer trust boundary; headers over Basic already work in every MCP client.
- **Edge-only gating** (tunnel or access proxy in front): leaves the app itself open inside the cluster and couples safety to infrastructure the app cannot verify; the app refusing to serve unauthenticated is self-contained.
