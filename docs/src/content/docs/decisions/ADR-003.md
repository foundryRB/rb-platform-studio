## Context

The deployed studio manages a clone it owns and publishes onboarding branches as pull requests. The local run points at a sibling checkout the operator commits with their own tools. Both are the same application.

## Decision

Git behavior lives behind the `GitPr` outbound port. The composition root wires `CliGitPr` (the managed clone plus the GitHub pulls API, authenticated with a fine-grained PAT) when `STUDIO_PLATFORM_REPO_URL` is set, and `NoopGitPr` over the operator's working tree otherwise. Use cases call the port unconditionally; no conditionals inside use cases.

## Rationale

- The capability difference between deployed and local is a wiring decision, decided once in the composition root, exactly like every other adapter choice in the hexagon.
- The no-op adapter keeps the local flow what it always was: the studio edits the working tree, the operator owns the commits.
- Use cases stay testable against a fake port; neither environment leaks into application logic.

## Alternatives considered and rejected

- **Mode flags inside use cases** (`if deployed: open PR`): scatters the environment across the application layer and multiplies test permutations; the hexagon exists to prevent exactly this.
- **A separate local build without git**: forks the application into two artifacts that drift; one artifact plus composition wiring keeps a single truth.
